## 推荐安装顺序

插件是**洋葱模型**（`compose`）：列表第 1 个在最外层，`next()` 之前按列表顺序往里走，
`next()` 之后按**倒序**往外返回。所以「排在前面」≠「一定最先生效」——写在 `next()` 后面的代码是最后才执行的。

一套通用组合：

| 顺序 | 插件 | 为什么在这个位置 |
| --- | --- | --- |
| 1 | 插件运行时间 | 洋葱模型的最外层：`next()` 之后才拿到耗时，排第一才量得到整条链（排最后永远是 0ms） |
| 2 | 交警贴条提醒 | 最紧急的路径，要抢在「智能设置通道」前面占住通道标记（后面那个看到已有通道就不动了） |
| 3 | 内容解码（base64） | 先把正文解出来，后面所有插件才能看到真实内容 |
| 4 | 消息验签（md5） | 验签算的是解码后的正文，必须排在 base64 之后 |
| 5 | 通知转文本 | 把通知监听转发进来的 JSON 换成正文 |
| 6 | 每日签到 | 只接管任务名带「签到」的定时任务，**必须排在「定时任务转待办」前面** |
| 7 | 定时任务转待办 | 接管剩下的定时任务（不接管的话 App 会丢弃这条消息） |
| 8 | 智能设置分组 / 智能设置通道 | 按关键词归类 |
| 9 | 分组头像 | 依赖上一步分好的组名，必须排在它后面 |
| 10 | 智能主题 | 给标题打上成功/失败/告警标记 |
| 11 | 纯链接转 URL、文本转图表 | 类型转换，放最后不影响前面的判断 |
| 12 | 转发到 Webhook | 把最终形态的消息转发出去 |

> 「每日签到」和「定时任务转待办」都会接管 `task` 消息，**先执行的赢**。
> 签到插件默认只处理任务名里带「签到」两个字（`CHECKIN_TASK_KEYWORD` 可改），
> 所以两者可以同时装：签到任务归签到插件，其余任务归待办插件。


## 消息 type 的修饰符写法

`type` 除了填正常类型，还可以用 `+` 连接**修饰符**，插件处理完会把真实类型还原回去：

| 写法 | 含义 |
| --- | --- |
| `base64+text` | 正文是 base64，解码后按 text 显示 |
| `md5+markdown` | 正文带 md5 签名，校验通过后按 markdown 显示 |
| `base64+md5+text` | 先 base64 解码，再验签，最后按 text 显示 |

签名约定：正文 + 空行 + 单独一行 `--` + 32 位十六进制 md5，
签名值 = `md5(正文 + MD5_SECRET)`，没配 `MD5_SECRET` 时就是 `md5(正文)`。

没装对应插件时，`type` 是这种写法会被 App 当成未知类型、退化成 `text` 显示，
所以这两组修饰符是「装了才生效、不装也不会坏」的。

## 交警贴条提醒怎么配

语音播报和循环通知都是**通道上的设置**，插件只负责把消息投到那个通道，所以要先把通道准备好：

1. 先让 App 建出这个通道：给自己发一条标题带 `[~交警]` 的消息（发送页直接发就行），
   Android 会自动建出名为「交警」的通道。
2. 抽屉 →「通知通道」→ 展开「交警」→ 打开**语音通知**和**重复通知**。
   重复间隔在消息设置里（默认 30 分钟）。
3. 打开「通知监听」，并在应用过滤里勾上短信 App —— 短信是靠监听短信应用的通知进来的。
4. 装这个插件（建议排在插件列表第二位，紧跟「插件运行时间」）。

通道名要和 `ALERT_CHANNEL` 完全一致（区分大小写），名字里别带空格和特殊字符，
它同时也是 Android 的 channel id。

**标题怎么来的**：命中之后插件把正文按 `。！？；` 切成句子，取**含车牌（或「交警」）的那一句**
当标题，顺手剥掉 `[2条]`、`【河南省交警】` 这类前缀 —— 原来的发送号码（如 `121234103`）不再当标题。
超长的句子按 `TITLE_MAX` 截断，完整原文仍然在正文里。

插件命中条件：正文里出现**车牌号**（含新能源 8 位）或**「交警」**二字。
想连自己的车牌一起盯，就把车牌填进 `PLATE_EXTRA`。

## 在 App 里安装

PushMe → 插件 → 右上角商店图标 → 选插件 → 安装。

装完之后可以在插件列表里调整顺序、临时关掉，也可以点进去改代码（改过之后商店会标成「本地已修改」，
再更新时会提示覆盖）。

> 需要配置的规则请写进**环境变量**，不要改代码：改过代码的插件会被标成「本地已修改」，
> 下次商店更新会覆盖你的改动。

## 写一个插件

一个插件就是一个 `.js` 文件，放在 [`plugins/`](./plugins) 下。文件头写一段 JSDoc，正文是**裸函数表达式**。
不想从头写就复制 [`plugins/_template.js`](./plugins/_template.js)（`_` 开头的文件不会被收录进商店）。

```js
/**
 * @key         pushme.my_plugin
 * @name        我的插件
 * @description 一句话说明这个插件做什么
 * @author      你的名字
 * @version     1.0.0
 * @tags        分组
 * @dependencies PMF.toast
 * @env         MY_KEY
 */
function(msg, next) {
    msg.title = '[#我的分组]' + msg.title
    next()
}
```

`msg` 只有四个字段可以改：`title` / `content` / `date` / `type`，`next()` 把消息交给下一个插件。

几条硬性要求，违反的话 App 会拒绝安装、或者让**所有插件一起失效**：

- **必须是裸函数表达式**，不能是 `module.exports = ...`，也**不要在末尾加分号**。
  App 是把所有插件的源码用 `plugins.push(...)` 拼成**一个** JS 程序跑的，多一个 `;` 就是语法错误。
- **不要在函数外面声明变量或函数**。同理，所有插件共享一个 JS 程序，两个插件都写
  `const KEY = 'x'` 会直接语法错误。所有代码都放进 `function(msg, next) { ... }` 里面。
- **不能出现 `require(` / `module.exports`**。
- **改代码就要升 `@version`**，否则用户永远收不到更新（脚本会直接报错拦住你）。
- **别把密钥写进代码**。用 `@env` 声明需要的环境变量，让用户自己填。

`@key` 建议显式写死（`pushme.xxx`）：默认取文件名，**改了文件名就等于换了个插件**，
用户那边会变成装了个新的、旧的还留着。

三个容易踩空的心智模型（详细见 [PLUGIN-SPEC.md](./PLUGIN-SPEC.md)）：

- **插件无状态**。每条消息都会新开一个 JS 上下文，`let count = 0` 这种计数下次就归零了。
- **异步改不了消息**。`PMF.fetch.asyncPost()` 返回时消息已经入库了，异步结果只能用来做副作用（转发、通知第三方）。
- **不调 `next()` 就是截断**，后面的插件都不会执行；反过来，想在某个条件下「什么都不做」，就用 `return next()` 提前退出。

## 维护本仓库

```bash
node gen-index.js
```

会做三件事：扫描 `plugins/`、重建 `index.json`、刷新上面那张表。
push 之后 GitHub Actions 也会跑一遍并把结果提交回来，所以本地忘了跑也不影响。

脚本会拦住两种手滑：

- 内容改了但 `@version` 没升 → 失败
- `versionCode` 比上一版小 → 失败
